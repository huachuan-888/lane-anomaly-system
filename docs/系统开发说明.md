# 车道线异常智能归因系统 · 系统开发说明

**项目**：D760 商用车 L2+ 智驾感知数据自动化分析
**规范来源**：带教老师《车道线异常智能归因系统》PPT + 《判断标准.txt》
**开发者**：东风商用车技术中心实习生
**完成时间**：2026年8月

---

## 一、项目概述

### 1.1 项目背景

商用车（D760 L2+ 智驾）在道路测试中，感知系统输出的车道线数据（CSV）与行车视频（TS）需要人工逐条排查异常问题，工作量大且容易遗漏。本系统基于《车道线异常智能归因系统》方案，将「问题表 → 感知数据 → 行车视频 → 异常检测 → 归因分析」全流程自动化。

### 1.2 项目目标

- 依据问题表（xlsx，33 个问题）自动定位对应的感知 CSV 与行车视频
- 依据判断标准五大规则自动检测车道线异常（缺失/抖动/宽度/可视范围/事件链）
- 对每个错误点抽取视频帧，进行清晰度评估与双维度校验（CSV 异常 vs 画面实测）
- 生成结构化可视化报告（HTML/MD），支撑异常归因结论
- 提供多种使用形态：Web 系统、桌面版 exe、命令行流水线、AI 技能

### 1.3 输入数据

| 数据 | 说明 |
|------|------|
| V1.1.6版本测试问题.xlsx | 测试问题表（33 个问题：编号/日期/时间/归类/描述/环境）|
| 同类型CSV_lane_mark_camera_list_1/ | 车道线感知数据（106 个 CSV，每段 10 分钟）|
| 视频/（6.16/6.17/6.18）| 行车视频（59 个 TS，每段 1 分钟，文件名=起始时刻）|

## 三、数据规范理解（关键破译）

### 3.1 CSV 字段语义

感知 CSV 按行存储车道线检测结果，每帧约 25 行：

| 字段 | 语义 |
|------|------|
| `lane_marks(0)~(7)` | 车道线槽位数组（0~7 共 8 个槽位，槽位≠车道线 ID）|
| `lane_marks(N).id` | 车道线 ID：**1=本车道左侧、-1=本车道右侧**、2/-2=相邻车道、99=无效 |
| `lane_marks(N).c0` | 车道线横向偏移（米）|
| `view_range_end` | 车道线纵向可视距离（100m 正常、<30m=前兆、0=无效）|
| `quality` | 检测质量（本版本数据恒=3，不可作为丢失信号）|
| `lane_mark_type` | 车道线类型（丢失槽位为占位值 1）|

### 3.2 核心判定原则

> **只关注本车道线（id=1 左侧 / id=-1 右侧），相邻车道线不参与异常判定。**

判定丢失必须检查 id=1/-1 是否在槽位中（不能只看 (6).id）。

### 3.3 视频时间对齐

- 视频文件名 `ND02512_105841_vedio_chn4.ts` → 起始时刻 = 10:58:41
- 帧号公式：`帧号 = (目标秒 − 视频起始秒) × 25 + 3`（25fps，3 帧补偿）
- 错误点必须在视频覆盖范围内才抽帧，否则显示"📭 无视频帧"（绝不硬截视频开头）
- 按 CSV 文件名日期匹配对应视频子目录（6.16/6.17/6.18），禁止跨日期

## 四、判断规则引擎（五大规则）

| 规则 | 判定条件 | 说明 |
|------|---------|------|
| **规则一 缺失** | 本车道 id=1/-1 不在槽位中 | 最强丢失信号 |
| **规则二 抖动** | \|ΔC0\| ≥ 0.2 连续 3 帧 | 横向偏移突变 |
| **规则三 宽度** | ≤3.4m 过窄 / ≥4.0m 预警 / ≥4.1m 持续 5 帧降级 | 双阈值 |
| **规则四 可视范围** | 单帧 ≥60m→<30m 骤降；持续 <30m 超 10 帧（≈1s）| 丢失前兆 |
| **规则五 事件链** | 丢失聚合间隔 ≤2s；前兆关联 ≤5s；含恢复时长 | 分"有前兆/突发"两类 |

**实测说明**：id=99 槽位 view_range_end 100% = 0（16388 次统计）；正常线 view_range_end 均值 100.0m。

## 五、双维度校验（CSV × 画面实测）

### 5.1 原理

CSV 规则检测出异常后，从视频抽取对应帧，用 **YOLOP 模型**（yolop-640-640.onnx）检测画面中的车道线，实测左右线位置与宽度，与 CSV 判定交叉验证。

### 5.2 结论分类（按标签类型分派）

| CSV 标签 | 画面判定 | 结论 |
|---------|---------|------|
| 丢失 | 两侧均有线 | ⚠️ 疑似感知误报 |
| 丢失 | 单侧有线 | 🔍 需人工复核 |
| 丢失 | 两侧无线 | ✅ 真实丢失 |
| 过宽/过窄 | 宽度比较 | ✅ 真实异常 / ⚠️ 感知误报 |
| 抖动 | 需多帧 | 🔍 待确认 |

### 5.3 画面侧丢失标注

画面仅检测到单侧车道线时，明确标注另一侧「车道线丢失」（如"仅检测到左侧车道线(639px), 右侧丢失"），与抖动/过宽标签同等级显示。

## 六、清晰度评估（5 指标）

对抽取的视频帧计算清晰度综合评分：

```
S = w1·L + w2·E + w3·C + w4·B + w5·F
```

| 指标 | 含义 |
|------|------|
| L | Laplacian 梯度（锐度）|
| E | 边缘密度（Canny）|
| C | 对比度 |
| B | Brenner 梯度 |
| F | FFT 高频能量 |

报告区分左右车道线清晰度，并与真实场景验证。

## 七、可视化报告

深色主题 HTML 报告（与《错误点复核报告.html》同款）：

- 统计卡：问题数 / 错误点数 / 截图数 / 双维度结论分布
- 趋势条形图：按问题 / 类型 / 校验结论
- 折叠问题卡片：编号/时间/归类/描述/环境/天气 + **CSV✅ 视频✅❌ 状态标记**
- 每个错误点：时间 / 错误类型标签 / 3 张截图（b-1s/b0s/b+1s，时间逐秒对应）/ 清晰度 / 双维度校验 / 画面侧丢失标注
- 规则五事件链：🔵 有前兆 / 🔴 突发 + 持续时长
- 场景识别：天气（晴/阴/小雨）+ 道路环境（隧道/弯道/分合流/鱼骨线等）

## 八、关键难点与解决方案

### 8.1 TS 视频解码坑

| 现象 | 解决 |
|------|------|
| `cap.set(POS_FRAMES)` 跳帧无效 | 必须顺序读帧 |
| `CAP_PROP_FRAME_COUNT` 返回负数垃圾值 | 不依赖该接口 |
| 帧整体偏暗（亮度峰值<150）| CLAHE 增强后再检测 |

### 8.2 时间对齐铁律

- 视频文件名 = 起始时刻，帧号 = (b秒−起始)×25+3
- 错误点必须在 [vstart, vstart+60] 内才抽帧，否则诚实显示"无视频帧"
- 按 CSV 日期匹配同日期视频子目录，禁止跨日期

### 8.3 车道线画面标注的教训

Hough 变换画线迭代 8 版（最长线段→消失点拟合→CLAHE→用户标定窄区）均未达到精度要求——**合流口+暗光场景下 Hough 检测不到本车道线（算法极限）**。结论：复杂场景应直接用深度学习（YOLOP 掩码），画面标注并非双维度校验必需（宽度已有 YOLOP 支撑）。

### 8.4 exe 打包坑

| 现象 | 解决 |
|------|------|
| exe 控制台 GBK 打印 emoji 崩溃 | 启动打印去 emoji + UTF-8 reconfigure |
| subprocess 调 python 失效 | 改为直接调用已 import 的引擎函数 |
| 硬编码路径新电脑失效 | 数据目录自动探测（exe旁"数据"→exe目录→环境变量）|
| 视频匹配不到 | 匹配窗口放宽（vstart-120s）+ 递归扫描任意目录结构 |

### 8.5 前端细节

- "展开全部错误点"无反应：`display:''` 会回退到 CSS `display:none`，须显式设 `block`
- 错误点截图上限 10→25（展开全部后均可见）

### 8.6 编码坑

PowerShell `Add-Content` 写中文默认 GBK，污染 UTF-8 仓库导致 README 乱码——**所有文件写入统一用 Python `open(path, encoding='utf-8')`**。

├── 车道线归因系统.exe   ← 双击启动

## 十一、开发协作流程（历程回顾）

1. **需求理解**：拆解 PPT《车道线异常智能归因系统》，提取三规则 + 5 指标规范
2. **数据破译**：解析 CSV 槽位结构、id 语义、view_range_end、视频时间对齐
3. **规则落地**：实现五大规则引擎（含用户多次实测纠正，如"只关注本车道线"）
4. **双维度校验**：YOLOP 画面实测与 CSV 交叉验证，按标签类型分派结论
5. **视频帧对齐**：攻克 TS 解码、日期对应、时间逐秒对齐
6. **画面标注探索**：Hough 八版迭代未达精度，经评估终止（算法极限）
7. **三方案交付**：Web 系统 / 桌面版 exe / 命令行 + Hermes 技能
8. **用户反馈迭代**：展开按钮、数据自动检测、新电脑适配、编码修复
9. **GitHub 备份**：代码 + 判断标准 + 模型（Release）+ 技能 + README
