# 车道线异常智能归因系统 (Lane Anomaly Attribution System)

基于 **D760 王者6x4 自主一代 L2+ 智驾项目** 的车道线异常自动化分析平台。
从测试问题表出发，自动完成「数据定位 → 异常检测 → 视频抽帧 → 清晰度评估 → YOLOP双维度校验 → 规则引擎归因 → 报告输出」全流程。

---

## 🧩 功能全景（已实现）

### 1. Web 系统（Flask，浏览器操作，端口 5000）

| 功能 | 说明 |
|------|------|
| **仪表盘** | 统计卡：问题总数 / 车道线问题 / 蛇形问题 |
| **问题列表** | 33 个问题，含场景标签（隧道/弯道/分合流/昼夜/天气）|
| **单问题深度分析** | 基本信息 + 错误点 + b1±1s 三张抽帧 + 清晰度 + 双维度校验 + 丢失事件链 |
| **前后翻页** | 左右两侧悬浮按钮，滚动中随时切换上一个/下一个问题 |
| **📤 文件上传** | 网页拖拽/点击上传 问题表(xlsx) / CSV / 视频(ts)，视频自动按日期归档 |
| **⚡ 一键复核** | 调用命令行流水线跑全量分析，生成最新报告 |
| **性能优化** | 分析结果缓存（翻页秒开）+ 视频帧缓存 + 图片懒加载 + 错误点折叠 + 加载提示 |

### 2. 命令行流水线（车道线自动复核.py）

| 模块 | 功能 |
|------|------|
| ① 关键字筛选 | 自动筛选 车道线/压线/蛇形 相关问题行（+同义词）|
| ② CSV 数据定位 | 按时间戳匹配 106 个 CSV（10分钟窗口）|
| ③ 错误点扫描 | 5 类异常：缺失 / 抖动 / 过宽 / 过窄 / 可视范围骤降 |
| ④ 视频定位 | 按日期子文件夹 + 文件名时间戳匹配 TS 视频 |
| ⑤ 视频抽帧 | 顺序读帧（TS 跳帧不可靠）+ 3 帧补偿，b1±1s 三张 |
| ⑥ 清晰度评估 | S = w1·L + w2·E + w3·C + w4·B + w5·F（权重可配）|
| ⑦ 场景识别 | 隧道 / 弯道 / 分合流 / 昼夜 自动标注 |
| ⑧ 双维度校验 | **YOLOP 语义分割实测宽度** vs CSV 上报 → 自动归因 |
| ⑨ 规则五事件链 | 丢失聚合 + 前兆关联 + 恢复时长 |
| ⑩ 报告生成 | HTML（含异常趋势图 + 折叠卡片）+ Markdown 双格式 |

### 3. 规则引擎（对齐判断标准.txt + PPT）

| 规则 | 判定条件 |
|------|---------|
| 规则1 车道线缺失 | id=1（左）或 id=-1（右）不在检测列表 |
| 规则2 异常抖动 | \|C0(t) − C0(t−1)\| ≥ 0.2 且连续 3 帧 |
| 规则3 宽度异常 | 总宽 ≤3.4m 过窄；≥4.0m 预警；≥4.1m 持续5帧降级 |
| 规则4 可视范围 | 从 ≥60m 骤降 <30m；或持续 <30m 超 10 帧 |
| **规则5 丢失事件链** | 同侧丢失帧间隔≤2s 聚合为一次事件；丢失前≤5s 有前兆 → "有前兆的丢失"；否则"突发丢失"；记录恢复时长 |

### 4. 车道线检测（YOLOP 深度学习）

| 功能 | 说明 |
|------|------|
| **语义分割** | YOLOP 模型：车道线 + 可行驶区域 + 目标检测（34MB ONNX）|
| **CLAHE 增强** | 适配画面偏暗场景（亮度峰值<150）|
| **单侧互补** | YOLOP 检到单侧时，另一侧用 Hough 补 |
| **置信度分级** | 车道线像素 <3000 → 判定"检测不可靠"，归入人工复核 |
| **模型回退** | 模型缺失时自动回退 Hough（仅提示）|

### 5. 双维度校验（核心创新，YOLOP 版）

```
CSV 报异常 + YOLOP 实测宽度 <4.0m   → ⚠️ 疑似感知误报
CSV 报异常 + YOLOP 实测宽度 ≥4.0m   → ✅ 真实异常
CSV 报丢失 + 画面检测到车道线         → ⚠️ 感知漏检
CSV 报丢失 + 画面未检测到            → ✅ 真实丢失
检测不完全 / 像素不可靠               → 🔍 需人工复核
```

## 🚀 快速开始

### 依赖

```bash
pip install openpyxl flask opencv-python numpy onnxruntime
```

### 下载模型（34MB）

```
https://github.com/huachuan-888/lane-anomaly-system/releases/download/v1.0-models/yolop-640-640.onnx
放到 models\yolop-640-640.onnx（无模型自动回退 Hough）
```

### 启动 Web 系统

```powershell
cd 车道线异常智能归因系统
python app.py
# 浏览器打开 http://127.0.0.1:5000/
```

或双击 `启动系统.bat`（自动打开浏览器，带端口检测/重启菜单）。

### 命令行全量复核

```powershell
python 车道线自动复核.py
# 输出到 自动复核输出/reports/错误点复核报告.html
```

## ⚠️ 技术要点（踩过的坑）

1. **TS 视频跳帧不可靠**：`cap.set(POS_FRAMES)` 对 TS 无效，必须顺序 `read()` 逐帧数
2. **开头帧补偿**：视频开头约 3 帧缓冲，帧号需 +3：`帧号=(b1秒−起始秒)×25+3`
3. **水印时间不可信**：开头含旧素材帧（06/07），对齐必须以 CSV 时间为准
4. **双维度校验**：画面清晰 ≠ 画面正常，必须检测实际车道线宽度（YOLOP），Hough 在合流口/暗光下会误判
5. **同一秒标签聚合**：每类型只保留最严重值（宽度 max / 可视 min），禁用字符串比较（Unicode 排序坑）
6. **函数内 import cv2**：否则 OpenCV 静默回退 Hough（YOLOP 检测失效）

## 📊 实测结果（V1.1.6 数据，YOLOP 版）

- 33 个问题，筛选出 20 个车道线/蛇形相关问题
- 检出 211 个错误点，322 张视频截图
- 双维度校验（YOLOP）：**15 真实异常 / 62 疑似误报 / 32 需人工复核**（Hough 版为 4/81/21——YOLOP 纠正了 9 个被 Hough 误判的真实异常）
- 规则五事件链：检出 1 条（#16 右侧丢失 2s，有前兆）
- 主要异常类型：车道线过宽 153 次 / 过窄 41 次 / 抖动 16 次
